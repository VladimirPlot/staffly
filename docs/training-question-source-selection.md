# Выбор источников вопросов

## Продуктовые правила

- Папка по умолчанию даёт вопросы только из самой папки. «Включая подпапки» расширяет область на активные ветки любой глубины. Отдельно скрытая ветка исключается целиком.
- «Все» и «Случайные N» применяются к выбранной области. Для публикации автор должен иметь доступ ко всем включённым папкам; недоступная область не включается молча.
- Прямые области родителя и ребёнка можно выбирать вместе. Пересекающиеся области нельзя: это сделало бы размер случайной выборки неоднозначным. Проверка есть и в интерфейсе, и на сервере.
- Отдельно выбранные вопросы обязательны. Случайная выборка берётся из остальных кандидатов; один вопрос никогда не дублируется в попытке. Добавление папки не удаляет ранее выбранные обязательные вопросы.
- Опубликованные аттестации используют снимок. Изменения банка, переносы и скрытие вопросов не меняют версию и прошлые результаты.
- Название, описание и аудитория сохраняются без обращения к содержимому банка. Изменение правил создаёт новую версию с прежними вопросами. Для актуализации вопросов есть отдельное действие «Обновить вопросы из банка»; сохранение изменённого состава требует подтверждения новой версии и отдельно предлагает перепрохождение всем.
- «Оставить опубликованные вопросы» отменяет обновление источников, сохраняя остальные изменения формы. Сама кнопка обновления ничего не публикует.
- Учебные тесты продолжают использовать живой банк; снимки и действие обновления относятся к аттестациям.
- Итоговое количество определяет серверный preflight. Для редактора существующего теста он проверяет ресторан, полномочия автора и editorRevision. Подготовка не берёт блокировки операций изменения; сохранение сохраняет прежний механизм блокировок и проверки ревизии.

## Интерфейс

ПК: широкий редактор с двумя панелями, выделение открытой папки, сворачивание веток, отдельные счётчики самой папки и подпапок. Мобильный экран: переключение «Папки / Вопросы», открытие папки переводит к её вопросам. Общий список выбранных источников позволяет удалить выбор вне текущей папки; недоступный исторический источник показывается по сохранённому ID.

В режиме опубликованного состава показаны версия и её количество вопросов; счётчики дерева явно обозначают текущее состояние банка. При пустом источнике или недостатке кандидатов есть пояснение. Для RANDOM можно дополнительно выбрать обязательные вопросы, для ALL уже включённые вопросы отмечены.

Подход к явной области категории и подкатегорий опирается на [Moodle Question categories](https://docs.moodle.org/403/en/Question_categories). Раздельные способы добавления отдельных вопросов и группы «все / случайные», а также видимый список источников — на [Canvas New Quizzes Item Banks](https://community.instructure.com/en/kb/articles/661082-unknown). Переключение панелей на мобильном экране — наше решение для доступной ширины, а не утверждение о мобильном интерфейсе этих продуктов.

## Проверка

Изолированный UI-стенд: `/tests/exam-editor-ux.html`, сценарий «Аттестация после переноса вопроса».

1. Открыть опубликованную аттестацию: источник выбран, в самой папке 0, в подпапке 1; итог опубликованной версии остаётся 1. Переименовать и сохранить без новой версии.
2. Нажать обновление: пустой источник не публикуется. Включить подпапки, открыть ребёнка: перенесённый вопрос отмечен как включённый. Сохранить через подтверждение версии.
3. Вернуться к опубликованным вопросам: исходные источники и опубликованное количество восстановлены; изменения названия/аудитории остаются.
4. Проверить прямые родительскую и дочернюю области, затем попытаться расширить родителя поверх выбранного ребёнка: пересечение отклоняется.
5. RANDOM N + отдельный обязательный вопрос: обязательный входит один раз, N выбирается из остальных. При нехватке кандидатов публикация отклоняется.
6. Скрыть ветку или перенести вопрос после публикации: сдача использует снимок. Исторические ссылки могут отсутствовать в живом банке; правки метаданных и новая версия правил сохраняют опубликованный состав.
7. На 390 px переключить панели, открыть вопрос, проверить сохранение выбора и подтверждение версии. Повторить на ПК.

Миграция V133 добавляет `include_descendants` с default false в живые и опубликованные источники. Старый JSON снимка остаётся читаемым; новый дополнительно фиксирует принадлежность кандидата к выбранным источникам, поэтому для запуска не требуется актуальная иерархия папок. Для ручной проверки изменений нужно перезапустить dev backend, чтобы применить миграцию.
